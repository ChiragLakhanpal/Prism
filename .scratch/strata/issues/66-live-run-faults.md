# 66: Five faults the first live runs found: the searcher's environment, a plan with no counts, a missing dependency, partial refusals of all-refused questions, and an unpaced document fetcher

**What to build:** The second session's first live runs of the agent scripts on October 26, 2026 (ticket 28 step 6, the refusal check) hit three faults that the fixture never showed. First, `src/strata/knowledge/search.py`'s `searcher_for` reads `os.environ` when no `environ` is passed, and `ops/agent/refuse_live.py`'s `create_app` call passes none, so every question whose agent called `search_passages` failed with `KeyError: 'AZURE_OPENAI_ENDPOINT'` even though the environment file holds it; `ops/agent/ask_live.py` builds its app the same way. Make the live scripts pass the environment they loaded to `create_app` (or make `create_app` thread its `environ` to `searcher_for`), so one load of the environment file serves every tool, and add a test that builds the app with an explicit environ and no matching process variable and sees `search_passages` get its settings. Second, `src/strata/tools/project_records.py` `_plans` (line 103, reached from `project_records` at line 210 through the agent's run_tool) raised `TypeError: 'NoneType' object is not subscriptable` at `counts["activities"]` for a plan whose counts are None, which crashed the tool for that project (seen for KE-NWWDA-541055-CW-RFB and for contract 1624689 of KE-KIMAWASCO-158691-CW-RFB); treat a plan with no counts as a plan with nothing counted (zero activities, a data note that says the counts are missing) and add a fixture case that reproduces it. Third, the inline `# dependencies` lists of `ops/agent/refuse_live.py` and `ops/agent/ask_live.py` lack `py3langid`, which ticket 42's language detection imports through the `/api/ask` stream; add it to both lists unless the second session's commit has already landed it (check `git log` for the file). Fourth, the live refusal check (`ops/agent/refuse_live.py`, 11 must-refuse questions) holds only 6 of 11: beyond the two project_records crashes, three runs end with "could not answer (agent_output): A partial refusal must answer the rest of the question with claims" or "Its refusal was partial, though the question asked only for what is refused" (refuse-live-tenders-criteria, refuse-personal-details, refuse-review-decisions; in another pass refuse-fraud-and-redactions instead), so the version 7 orchestrator agent chooses a partial refusal on questions where every part is refused, and which questions it picks shifts between runs. Tighten the orchestrator agent's instructions in the repo (the refusal section): when every part of a question falls under a refusal, refuse the whole question with the refusal's reason and no partial answer; a partial refusal is only for a question with an answerable rest, and then the rest must carry claims. Keep the harness's contract as it is. Prove it offline with the recorded refusal cases and the stand-in agent where they replay, and name the live rerun of `refuse_live.py` as the workspace step that proves it on Foundry (the second session runs it after the agent sync). Fifth, `ops/documents/run_live.py` (lines 111 and 112) builds `strata.reader.documents.LiveDocuments()` with no arguments, so it fetches with `strata.fixture.record.fetch_url`, plain urllib: no pause between requests, no cache in the bronze volume, no HostRefused stop on a 403. The paced, cached fetcher `PoliteFetch` is used only through `strata.lakehouse.readers.live()` (`readers.py` lines 89 to 95), which the nightly task takes; that is why the catch-up's document runs burst at documents.worldbank.org, get blocked, and refetch the oversized plan texts on every attempt (hours per run). Make the live script take `readers.live()` (or `LiveDocuments(fetch=PoliteFetch(...))`) so one fetcher serves the nightly task and the script, and add a test that the script's documents reader is built with the paced fetcher. Change no number, claim or tool contract.
