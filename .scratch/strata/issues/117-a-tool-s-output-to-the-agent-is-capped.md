# 117: A tool's output to the agent is capped, so one large result can no longer kill an answer

**What to build:** On October 28, 2026 at 03:01 UTC the demo-ready command's second run of the smoke question (search-passages-icr-rebidding, through the app's own routes in process on the paid workspace, agent strata-orchestrator version 10) ended with `agent_unavailable`: Foundry answered 400 `Invalid 'input[0].output': string too long. Expected a string with maximum length 10485760, but got a string with length 20831467 instead` (code string_above_max_length). The run six minutes before had passed all six checks with the same question, so the agent's first tool call differed, and that tool's result, serialized by `call_output` in `src/strata/agent/loop.py` (`json.dumps(output)` with no limit), was 20.8 million characters. Any question that leads the agent to such a tool fails the same way, with no answer and no check line, which is a demo risk on the ask box. Two parts: (1) find the tool: measure every tool's output size on the fixture and, with the env file, on the paid workspace for the demo projects (P130164 and P156634) with the arguments the agent uses (the question above, the project ids, the showcase package), name the one above 10 million characters in the ticket's done comment, and give it a row or size cap of its own in `config/tools.toml` (rule 9) that keeps what an answer needs (ids, the cited fields, the first rows) and says in the result that the rest is left out; (2) the general guard: in `call_output`, when the serialized output is longer than `agent.max_tool_output_chars` in `config/thresholds.toml` (400,000 to start), send a trimmed copy instead: the tool's top-level fields kept, each list cut to its first rows until the string fits, and a `truncated` note telling the agent that the rest was left out and to ask narrower; the full result still feeds `turn.facts`, so the verifier checks against the records the tool returned, and the agent can only cite what it saw. Prove it on the fixture: a tool result built to 11 million characters reaches Foundry's fake as a string under the cap with the note and the first rows, a normal result is unchanged byte for byte, and the recorded ask streams still pass; the live proof is the orchestrator's: the demo-ready command's smoke question passing twice in a row on the paid workspace after the merge and the App redeploy.
