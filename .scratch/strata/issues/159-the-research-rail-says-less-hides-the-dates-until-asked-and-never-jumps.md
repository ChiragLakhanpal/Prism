# 159: The research rail says less, hides the read dates until asked, and never jumps

**What to build:** The user's note on the progress rail (ticket 157) as it runs on the App for P130164, November 6, 2026 at about 00:45 PST: "too much information, the person using it is a procurement person, why tell them that it's run on what date for each step? if you want to show the run date, why not hide it until needed? think about the UX please. I like the UI, also test the micro animation and microinteraction, it's janky, and jumps around." Two changes to `web/src/components/ResearchProgress.tsx` and its copy under `research.progress`:

1. **Less on each row, the rest behind a disclosure.** Every row is one line: its icon and its label, and after the label, in `text-ink-muted`, only the result a procurement specialist needs: "kept 4 items", "kept one item", "kept no items", "not reached", "4 sentences" for writing, "checked 12 of 65 sentences" for checking. No dates on rows. The read date of a stored run appears once, in one sentence under the step count line (the existing `copy.research.readOnStored` wording: "I read these sources on November 5, 2026; the writing and the checks happen now."), and the per-source notes (a not-reached reason such as "The registry lists no news page for the agencies the project record names.", a read note such as "read on November 5, 2026") move into one `Disclosure` (`web/src/components/Disclosure.tsx`) under the rail, collapsed, labelled "Why a source was not reached" when any source was not reached and "About these sources" otherwise, holding one line per source with its note. A row never wraps: the label is clipped with an ellipsis at the column's width (`truncate`) and carries the full text in `title`. "Project facts" gets the result "read" so no row is bare and every row has the same height.
2. **Nothing jumps.** The rail must not shift any element as the stream goes on. Rules: every row has a fixed height (one line, the icon box 16 px, `items-center`); the icon swap (circle, spinner, check, minus) keeps the same 16 px box; the elapsed clock sits in a span with `font-variant-numeric: tabular-nums` and a fixed minimum width (`min-w-[3.5ch]` or the design system's equivalent), so "0:29" and "1:02" take the same room and the words after it stay put; the meter's fill changes width with a 300 ms ease transition and nothing else animates except the spinner's rotation; the disclosure's open state changes the page height only when a person opens it; with `prefers-reduced-motion: reduce` the transition and the spinner's rotation are off (the spinner then shows still, as `Steps` does if it does); the `key` of each row is the step's id, never its index, so a row never remounts; the rail's container reserves its height from the plan event (rows × row height) so the brief's arrival, not the stream, is the only moment the page re-flows. When the run ends, the rail is replaced by the brief as today.
3. **Tests.** In `web/tests/research.spec.ts`, a layout-shift test: with the mocked stream delivered one event at a time, record `getBoundingClientRect()` of the title line, the step count line, the meter, every row and the disclosure after the plan event, then after every later event (steps, sentences, the clock ticking past 0:59 with Playwright's clock), and assert every element's `top`, `left` and `height` are unchanged until the done event; assert no row's text wraps (each row's `scrollHeight` equals one line); assert the rows carry no date and the sentence under the step count carries it once; assert the disclosure is collapsed, opens on click, and lists the not-reached reason; run axe on the rail.
